# ТЗ: ComfySdk — .NET SDK для ComfyUI (Server + Cloud) + автогенерация параметров

Дата: 2026-02-14

## Что делаем
Нужен публичный **NuGet** под **.NET 10 (`net10.0`)**: клиент для **ComfyUI Server (self-hosted)** и **Comfy Cloud**, который:

- Отправляет workflow на генерацию (**HTTP**) и подписывается на прогресс (**WebSocket**) с автопереподключением.
- Умеет параллельно выполнять несколько запусков (несколько `RunHandle` одновременно).
- Работает с файлами как человек: разработчик даёт **path / URL / base64 / Stream / byte[]**, SDK сам приводит к единому формату и при необходимости загружает.
- Позволяет выбирать **какие outputs ждать и скачивать** (картинки, видео, аудио, прочие артефакты) — это задаётся в `settings.<workflow>.json`.
- Имеет генератор: пара `workflow.json` + `settings.<workflow>.json` → **типизированный класс параметров**, который потом материализуется в готовый workflow и выполняется.

### Важные принципы
- Генерация классов **не запускает** ComfyUI и не “магичит”: она создаёт удобный контракт параметров.
- Основной способ найти узел — **селектор** (по `class_type` + условия), `nodeId` — опционально.
- Если `requireSingle=true`, селектор обязан дать ровно один матч; иначе это ошибка генерации.
- Path-синтаксис в settings: dot-path + массивы, например `inputs.seed` и `inputs[0].image`.
- Все “непонятки” по структуре workflow ловим **на этапе генерации**: если патч никуда не применим — генератор падает и объясняет почему.

## Что не делаем в v1
- Не делаем UI и визуальный редактор settings.
- Не обещаем “автоматически починить любой workflow”.
- `Cancel` в runtime означает “перестаём ждать локально”, без авто-вызова `/interrupt`.

## Пакеты (предложение)
- `ComfySdk` — публичный API + runtime (клиент, run/stream, download, файлы, ошибки).
- `ComfySdk.Generator` — генератор классов (CLI / MSBuild target — по минимуму).
- `ComfySdk.Samples` — примеры.

## Поддержка ComfyUI
- **Server**: стандартные роуты `/prompt`, `/history`, `/view`, `/upload/...`, `/interrupt` + WS `/ws`.
- **Cloud**: поддержка `/api/...`, `history_v2`, `view` с редиректами (302) и токенами.

## Logging
- `Microsoft.Extensions.Logging` + маскирование секретов (токены/куки/ключи).
- Секреты храним в ENV/user-secrets/конфиг-провайдерах приложения.
- `settings.*.json` содержит только workflow/patches/outputs, без токенов и ключей.

## Определение готовности Run
- Основной путь: WS события успех/ошибка + подтверждение по history при необходимости.
- Фоллбек: если WS отвалился — можно добрать состояние по HTTP.

## Допущения
- Workflow экспортирован из ComfyUI “как есть” и содержит корректные `class_type`.
- Settings Spec проходит валидацию генератором до runtime.
- Для Cloud допускаем отличия маршрутов, поэтому используем `ApiPrefix`/`RouteMap`.
